# Phone frames

Rear Screen can show the rear screen **inside a phone**: live mirror, photos and videos, with the camera module drawn around it.
It is optional — the **Frame** menu always starts on **No frame**, and you can go back to it at any time.

| | macOS | Windows |
|---|---|---|
| Live mirror in the frame | ✅ (view only — no touch control in this mode) | not yet |
| Photos in the frame | ✅ (saved next to the plain photo, `…_cadre.png`) | ✅ |
| Videos in the frame | ✅ (re-rendered when the recording ends, `…_cadre.mp4`) | not yet |

Frames apply to the **rear screen** only; the front screen is never framed.

## Transparent background
Frames have a **transparent background** by default: in the live window the desktop shows through around the phone (with a shadow that follows its shape),
and photos are saved as transparent PNGs. A frame can ask for a black background instead (`"background": "black"` in `frame.json`).
**Videos are the exception:** an MP4 cannot be transparent (H.264 has no transparency), so framed videos always have a black background.

## Built-in frame
**Default** is an original illustration drawn for this project (no manufacturer artwork). It follows the layout of a Xiaomi 18 Pro Max:
the rear display inside the camera island, two lenses stacked on its left, the secondary sensor and flash below.
It is regenerated by [`scripts/make-frame.py`](../scripts/make-frame.py).

## Use your own frame
A frame is a folder with two files, in **your personal folder** (never in the repository):

| System | Folder |
|---|---|
| macOS | `~/Library/Application Support/Rear Screen/frames/<name>/` |
| Windows | `%APPDATA%\RearScreen\frames\<name>\` |

- `frame.png` — the phone image (RGBA) with a **transparent hole** where the screen goes
- `frame.json` — where the screen is (and an optional background)

Rear Screen lists every folder found there in the **Frame** menu (press ↻ or reopen the app after adding one).
The menu's last entry, *Open frames folder…*, opens the folder for you.

### Make a frame from any phone picture
[`scripts/make-custom-frame.py`](../scripts/make-custom-frame.py) cuts the screen out of an image and writes the folder above (Python 3 + Pillow):

```bash
# 1) find the coordinates: writes a grid image with pixel positions
python3 scripts/make-custom-frame.py phone.png --grid

#    …or detect the screen from the colour of what it displays
python3 scripts/make-custom-frame.py phone.png --detect-color 120,110,240

# 2) create the frame: screen at x=162,y=128, 1052×646 px, rounded corners of 72 px,
#    and keep the two lenses visible on top of the screen
python3 scripts/make-custom-frame.py phone.png --name my-phone \
    --screen 162,128,1052,646 --radius 72 \
    --keep-ellipse 323,289,137,137 --keep-ellipse 323,611,137,137
```

It writes `frame.png`, `frame.json` and a `preview.png` (sample content behind the hole) so you can check the fit and adjust the numbers.
To make the plain background of a render transparent too, add `--remove-background` (it clears the uniform colour connected to the image edges; `--bg-tolerance` adjusts it).
Other options: `--keep-rect` (keep a rectangular area), `--background black|transparent` (default `transparent`), `--max-size`, `--out`.
The tool **refuses to write inside the repository**, so brand images stay on your machine.

> **Rights:** only use images you are allowed to use. Press renders and product photos belong to their owners — keep them in your personal
> frames folder, do not commit or redistribute them.

## How it works (macOS live mode)
scrcpy cannot draw a frame around its window, so in frame mode the app reads the phone's H.264 video stream itself (the scrcpy server,
started over `adb`) and decodes it with the system's hardware decoder, in a borderless window shaped like the phone.
Drag the window to move it; hover it to reveal the close button, or press Esc. When recording, the file is still captured by scrcpy;
the framed video is produced from it afterwards.
